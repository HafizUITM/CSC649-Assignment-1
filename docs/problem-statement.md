# Part A: Problem Formulation

## A1. Problem Statement
Retail investors utilizing the Public Gold platform face high cognitive fatigue and severe task friction due to visual clutter, fragmented navigation modules, and manual transaction verification methods. Specifically, users attempting to transition between digital gold savings (GAP) and physical installment management (EPP) must navigate disconnected sub-interfaces and manually upload bank transfer payment slips. This cumbersome process delays transaction fulfillment, increases user drop-offs, and reduces user trust during time-sensitive market price fluctuations.

## A2. Users and Scope

### Target Users & Stakeholders
* **Digital Gold Investors (GAP Users):** Want to confirm the current gold price quickly, convert between Ringgit and grams, and see their holdings update immediately after buying or selling.
* **Installment Buyers (EPP Users):** Require visual payment progress tracking, automated payment schedules, and clear installment due date notifications. The user want to see how far along their payment plan is, know when the next payment is due, and be reminded in time.
* **Physical Bullion Shoppers:** Require streamlined catalog browsing, transparent branch pickup locator maps, and secure delivery tracking options. It is to browse the catalog easily, find a pickup branch, and track delivery.
* **Platform Administrators:** Benefit from automated payment verification, reducing manual receipt slip verification workloads. Not users of the redesigned interface, but they benefit from a clearer payment confirmation flow that reduces manual slip checking.

### Project Scope
* **In-Scope:** Heuristic evaluation, fishbone root-cause mapping, Information Architecture (IA) restructuring, high-fidelity Figma web/mobile wireframes, 3-step checkout workflow design, and System Usability Scale (SUS) evaluation planning.
* **Out-of-Scope:** Full-stack backend database engineering, live banking payment gateway API deployment, and production server hosting.
* **Assumptions and constraints:**Payment verification is simulated in the prototype. Automated verification is treated as a future integration.
The branch locator and delivery tracking are secondary and will be addressed only if time allows.
